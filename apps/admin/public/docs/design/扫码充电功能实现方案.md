# 扫码充电功能实现方案

## 一、功能概述

扫码充电是充电站管理系统的核心功能之一，用户通过扫描充电桩上的二维码快速启动充电服务。该功能涉及管理端（二维码生成与管理）和用户端（扫码充电）两个模块的协同开发。

### 1.1 功能特点

- ✅ **多种扫码方式**：支持小程序原生扫码、H5手动输入
- ✅ **多格式兼容**：支持 `PILE_123`、纯数字、JSON 等多种二维码格式
- ✅ **实时状态显示**：充电桩状态、价格、功率等信息实时展示
- ✅ **完整充电流程**：扫码 → 确认信息 → 开始充电 → 实时监控 → 停止充电
- ✅ **管理端协同**：管理员可在管理端生成、查看、下载充电桩二维码

### 1.2 业务流程

```
用户流程：
扫码/输入编号 → 获取充电桩信息 → 确认充电信息 → 开始充电 → 充电中监控 → 停止充电 → 结算支付

管理端流程：
查看充电桩列表 → 选择充电桩 → 查看/生成二维码 → 下载/打印二维码 → 张贴到充电桩设备
```

## 三、功能实现细节

### 3.1 二维码格式规范

#### 3.1.1 标准格式（推荐）

**格式1：前缀格式**
```
PILE_{充电桩ID}
示例：PILE_123
```

**格式2：纯数字格式**
```
{充电桩ID}
示例：123
```

**格式3：JSON格式**
```json
{
  "pileId": 123,
  "stationId": 1,
  "type": "fast"
}
```

#### 3.1.2 二维码内容设计

- **基础信息**：充电桩ID（必填）
- **扩展信息**：站点ID、类型（可选，用于快速识别）
- **版本标识**：可用于后续功能扩展

### 3.2 后端接口设计

#### 3.2.1 扫码获取充电桩信息（已有）

**接口**：`POST /api/mobile/charging/scan`

**请求参数**：
```json
{
  "qrCode": "PILE_123"  // 二维码内容
}
```

**响应数据**：
```json
{
  "code": 200,
  "data": {
    "pileId": 123,
    "stationId": 1,
    "stationName": "北京朝阳充电站",
    "pileName": "1号桩",
    "type": "fast",          // fast/slow
    "power": 120,            // 功率 kW
    "price": 1.2,            // 电价 元/度
    "status": 1              // 1空闲 2充电中 6故障/离线
  }
}
```

#### 3.2.2 获取充电桩二维码（新增）

**接口**：`GET /api/piles/:id/qrcode`

**请求参数**：
- 路径参数：`id` - 充电桩ID
- Query参数（可选）：
  - `format`: 二维码格式（`PILE_123` | `json` | `number`），默认 `PILE_123`
  - `size`: 二维码尺寸（`small` | `medium` | `large`），默认 `medium`
  - `includeInfo`: 是否包含扩展信息（boolean），默认 `false`

**响应数据**：
```json
{
  "code": 200,
  "data": {
    "qrCode": "PILE_123",           // 二维码文本内容
    "qrCodeImage": "data:image/png;base64,...",  // 二维码图片（Base64）
    "pileId": 123,
    "stationName": "北京朝阳充电站",
    "pileName": "1号桩",
    "downloadUrl": "/api/piles/123/qrcode/download"  // 下载链接
  }
}
```

#### 3.2.3 下载充电桩二维码（新增）

**接口**：`GET /api/piles/:id/qrcode/download`

**请求参数**：
- 路径参数：`id` - 充电桩ID
- Query参数：
  - `format`: 下载格式（`png` | `svg` | `pdf`），默认 `png`
  - `size`: 二维码尺寸（像素），默认 300

**响应**：返回二维码图片文件流

## 四、数据库设计

### 4.1 现有表结构（无需修改）

**pile 表**（充电桩表）
- `id`: 充电桩ID（主键）
- `station_id`: 所属充电站ID
- `name`: 充电桩名称
- `type`: 类型（快充/慢充）
- `status`: 状态（1空闲 2充电中 6故障/离线）
- `power`: 功率
- `price`: 电价

**order 表**（订单表）
- `order_no`: 订单号
- `user_id`: 用户ID
- `pile_id`: 充电桩ID
- `status`: 订单状态（2充电中 3已完成）
- `start_time`: 开始时间
- `end_time`: 结束时间

### 4.2 可选扩展（后续考虑）

如果需要记录二维码生成历史，可新增表：

```sql
CREATE TABLE `pile_qrcode_log` (
  `id` BIGINT AUTO_INCREMENT PRIMARY KEY,
  `pile_id` BIGINT NOT NULL COMMENT '充电桩ID',
  `qr_code_content` VARCHAR(255) NOT NULL COMMENT '二维码内容',
  `format` VARCHAR(50) COMMENT '二维码格式',
  `generated_by` BIGINT COMMENT '生成人ID',
  `generated_at` DATETIME DEFAULT CURRENT_TIMESTAMP COMMENT '生成时间',
  KEY `idx_pile_id` (`pile_id`),
  FOREIGN KEY (`pile_id`) REFERENCES `pile`(`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='充电桩二维码生成记录';
```

## 七、技术难点和解决方案

### 7.1 二维码生成

**难点**：需要支持多种格式，并且要保证兼容性

**解决方案**：
- 使用成熟的二维码生成库（qrcode）
- 标准格式优先使用 `PILE_{ID}` 格式
- 向后兼容纯数字格式

### 7.2 小程序扫码兼容

**难点**：小程序和H5的扫码方式不同

**解决方案**：
- 使用 uni-app 的条件编译
- 小程序使用原生 camera 组件
- H5提供手动输入作为备选方案

### 7.3 充电状态实时同步

**难点**：需要实时更新充电状态和数据

**解决方案**：
- 使用轮询机制（每3-5秒请求一次）
- 可以使用 WebSocket（后续优化）
- 充电页面自动刷新状态

### 7.4 二维码下载和打印

**难点**：不同浏览器的下载行为可能不同

**解决方案**：
- 使用 Blob URL 实现下载
- 提供多种格式选择（PNG、PDF）
- 使用第三方库实现PDF生成（如 jsPDF）

## 九、风险评估

### 9.1 技术风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 二维码识别失败 | 中 | 低 | 提供手动输入备选方案 |
| 小程序扫码权限被拒绝 | 中 | 中 | 友好提示，引导用户授权 |
| 网络不稳定导致充电中断 | 高 | 中 | 添加重试机制，本地缓存订单状态 |
| 二维码格式不兼容 | 低 | 低 | 支持多种格式解析 |

### 9.2 业务风险

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|----------|
| 用户余额不足 | 中 | 中 | 充电前检查，引导充值 |
| 充电桩被占用 | 中 | 中 | 实时状态检查，友好提示 |
| 充电异常中断 | 高 | 低 | 记录异常日志，支持手动停止 |
