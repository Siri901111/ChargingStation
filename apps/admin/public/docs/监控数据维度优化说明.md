# 监控数据维度优化说明

## 概述

本次优化重新设计了监控数据的维度和展示方式，解决了管理员端无法清晰显示页面路径和用户名的问题。

## 完成的优化

### 1. 数据模型增强

#### 新增字段

在 `monitor_data` 表中添加了以下维度字段：

- **page_path** (VARCHAR(500))
  - 规范化后的页面路径
  - 用于清晰的页面展示
  - 优先级：`extra.routePath` > `extra.toRoute` > `data.path` > `data.to` > 从 `page_url` 提取

- **user_display_name** (VARCHAR(100))
  - 用户显示名称
  - 从多个来源提取：`extra.userName` > `extra.name` > `sessionInfo.userId` > `userId`
  - 用于展示友好的用户名称

- **platform** (VARCHAR(20))
  - 平台类型（web、uniapp等）
  - 从 `extra.platform` 提取

- **env** (VARCHAR(20))
  - 环境标识（h5、mp-weixin等）
  - 从 `extra.env` 提取

#### 索引优化

添加了以下索引以提升查询性能：
- `idx_page_path` - 页面路径索引
- `idx_platform` - 平台类型索引
- `idx_user_display_name` - 用户显示名称索引

### 2. 数据保存逻辑优化

#### 提取函数

**extractPagePath()** - 页面路径提取
```typescript
优先级：
1. extra.routePath
2. extra.toRoute
3. data.path
4. data.to
5. 从 pageUrl 提取路径
```

**extractUserDisplayName()** - 用户显示名称提取
```typescript
优先级：
1. extra.userName
2. extra.name
3. 从 sessionInfo.userId 生成
4. 从 userId 生成
```

**extractPlatformInfo()** - 平台信息提取
```typescript
从 extra 中提取：
- platform: extra.platform
- env: extra.env
```

### 3. 数据查询优化

#### 增强返回数据

在查询返回时，自动增强数据：
- **用户信息**：`user_display_name` > `user.name` > `user_id` > "匿名"
- **页面信息**：`page_path` > 从 `page_url` 提取 > `page_title`

### 4. 前端展示优化

**改进项**：

### 5. UniApp 端集成

#### 用户信息上报

在用户登录后，自动设置用户信息到监控SDK：

```typescript
// 设置用户ID和额外信息
monitor.setExtra({
  userId: String(userInfo.id),
  userName: userInfo.name || userInfo.phone || `用户${userInfo.id}`,
  name: userInfo.name,
  phone: userInfo.phone,
})
```

#### 路由信息上报

创建了 `monitor-mixin.ts` 工具，方便在页面中上报路由变化：

```typescript
import { useMonitorPage } from '@/utils/monitor-mixin'

onLoad((options) => {
  useMonitorPage(options)
  // 自动上报页面访问和路由信息
})
```

1. **备份数据库**
   ```bash
   mysqldump -u root -p your_database > backup.sql
   ```

2. **执行迁移脚本**
   ```bash
   mysql -u root -p your_database < apps/server/src/migrations/add-monitor-dimensions-mysql.sql
   ```

3. **验证迁移结果**
   ```sql
   SELECT COLUMN_NAME, COLUMN_TYPE, IS_NULLABLE, COLUMN_COMMENT
   FROM INFORMATION_SCHEMA.COLUMNS
   WHERE TABLE_SCHEMA = DATABASE()
     AND TABLE_NAME = 'monitor_data'
     AND COLUMN_NAME IN ('page_path', 'user_display_name', 'platform', 'env');
   ```

## 注意事项

1. **数据库迁移**：执行迁移前请务必备份数据库
2. **历史数据**：新字段允许 NULL，不会影响现有数据
3. **新数据**：新上报的数据会自动填充所有维度字段
4. **索引**：新增的索引会提升查询性能，但会增加存储空间

## 后续优化建议

1. **历史数据填充**：如果需要，可以执行迁移脚本中的 UPDATE 语句为历史数据填充新字段
2. **页面路由追踪**：可以在 UniApp 页面中统一使用 `useMonitorPage` 混入自动追踪路由
3. **用户映射**：如果监控SDK的 userId 与系统用户表关联，可以建立映射关系以获取更准确的用户信息
